# mono.

Дизайн-студия: карточки WB/Ozon, сайты, брендинг. Основной сайт на Next.js (App Router).

## Структура

```
app/                  — страницы Next.js (App Router)
  web/                — страница «Сайты» (продаёт результат через пакеты)
  wbdesign/           — страница «E-commerce»
  brand/              — страница «Brand»
components/
  web/                — компоненты страницы /web (hero, packages, calculator, faq, cases, form)
content/web/          — контент страницы /web (JSON, редактируется без правок кода)
lib/
  content.ts          — загрузчик JSON-контента
  web-types.ts        — TypeScript-типы контента
wbgen/                — генератор карточек WB (отдельный инструмент)
```

## Страница /web — управление контентом

Весь контент страницы /web живёт в JSON-файлах (`content/web/`). Никакие цены, пакеты, FAQ и кейсы не хардкодятся в компонентах.

### Как добавить/изменить пакет

Файл: `content/web/web_pricing.json`, массив `packages`.

```json
{
  "id": "growth",
  "name": "Рост",
  "price": "от 80 000 ₽",
  "badge": "Выбирают чаще",
  "for": "Бизнесы с оборотом 500k–3M ₽/мес",
  "includes": ["Многостраничный сайт", "Онлайн-запись"],
  "roi": "20–35 новых клиентов в месяц",
  "term": "2–3 недели",
  "cta": "Обсудить проект"
}
```

- `badge: null` — бейдж не отображается
- `for` — кому подходит (отображается под ценой)
- `roi` — строка окупаемости (отображается в карточке)
- `includes` — массив строк (чеклист состава пакета)

### Как добавить FAQ

Файл: `content/web/web_faq.json`, массив объектов `{ q, a }`.

```json
{ "q": "Вопрос?", "a": "Ответ с [плейсхолдером]." }
```

Первый вопрос раскрыт по умолчанию. Плейсхолдеры в `[квадратных скобках]` оставляются как есть — это маркеры для ручной подстановки на звонке.

### Как добавить кейс с метриками

Файл: `content/web/web_cases.json`. Стартово — пустой массив `[]`.

Если кейсов нет — секция отображает плашку «Кейсы в работе» с формой «Узнать первым». Никаких фейковых цифр.

Когда кейс появляется:

```json
{
  "slug": "salon-moscow",
  "client": "Салон «Имя»",
  "niche": "Салон красоты",
  "year": 2026,
  "cover": "/cases/salon-cover.jpg",
  "metrics": [
    { "label": "Конверсия", "before": "1.2%", "after": "4.5%", "delta": "+3.3pp" },
    { "label": "Заявки/мес", "before": "12", "after": "38", "delta": "+26" }
  ],
  "quote": "Текст цитаты клиента",
  "period": "3 месяца после запуска"
}
```

**Правило:** цифры — только подтверждённые. Если метрики нет — кейс не публикуется или помечается как «Концепт» без ROI-обещаний.

### Как изменить гарантии

Файл: `content/web/web_guarantees.json`, массив `{ title, text }`. Формулировки только о доработках, сроке и метриках — никакого возврата денег.

### Как изменить калькулятор

Файл: `content/web/web_calculator.json`:
- `fields` — массив полей (select/number) с `id`, `label`, `options`/`placeholder`
- `output_template` — шаблон вывода (подстановки: `{clients}`, `{check}`, `{revenue}`, `{payback}`)
- `disclaimer` — предупреждение под результатом

### Как изменить процесс

Файл: `content/web/web_process.json`, массив шагов `{ num, title, term, artifact }`.

### Квалификация и позиционирование

Файл: `content/web/web_pricing.json`:
- `positioning` — eyebrow, h1 (массив из 2 строк), sub
- `anchor` — строка-якорь под CTA
- `qualification.ideal` — карточки «идеальный клиент»
- `qualification.not_fit` — честная строка «не работаем с…»
- `price_drivers` — блок «Что влияет на цену»

## Деплой (GitHub Pages)

Сайт публикуется статикой на GitHub Pages автоматически: пуш в `main` запускает
`.github/workflows/deploy.yml`, который собирает `npm run build:static` и
выкладывает каталог `out/` в Pages.

```bash
npm run build:static   # то же, что делает CI: статический экспорт в ./out
```

Что важно знать про статику:

- `scripts/build-static.mjs` включает `output: 'export'` и после сборки
  перекладывает OG-картинку: Next выкладывает роут `/api/og` файлом без
  расширения (`out/api/og`), поэтому в метаданные уходит `/og.png`.
- Серверных роутов в статике нет: `POST /api/lead` и `/api/design-lead` на
  Pages не работают (Next помечает их как Dynamic и пропускает), форма сама
  показывает запасной канал «Написать в Telegram». Чтобы лиды писались в
  Supabase и Telegram, нужен хостинг с Node: обычная сборка (`npm run build` +
  `npm start`) на Vercel / Render / Railway.
- Роуты `robots.txt`, `sitemap.xml` и `/api/og` помечены
  `export const dynamic = 'force-static'` — без этого `next build` с
  `output: 'export'` падает на этапе сбора данных страниц.
- Публичные адреса берутся из переменных сборки: `NEXT_PUBLIC_SITE_URL` — корень
  сайта **вместе с подкаталогом деплоя** (для Pages это
  `https://ortamy.github.io/mono`), `NEXT_PUBLIC_BASE_PATH` — тот же подкаталог
  для маршрутизации Next. В метаданные подкаталог не подмешивается: подставляйте
  его внутри `NEXT_PUBLIC_SITE_URL`, иначе получите `/mono/mono/...` в canonical
  и OG-картинке.

## Аналитика (события)

Если подключена аналитика, компоненты эмитят события:
- `package_view{id}` — просмотр пакета
- `calc_run` — запуск калькулятора
- `faq_open{q}` — открытие вопроса
- `form_submit{turnover_range}` — отправка формы с диапазоном оборота

## Запреты

- Никаких «1500% годовых», «гарантированного потока клиентов», возврата денег как гарантии
- Никаких выдуманных цифр в ROI без кейсов — только диапазоны и сноски «по кейсам студии»
- Визуальный язык mono (тёмный editorial, hairlines, Inter + DM Mono) не меняется
