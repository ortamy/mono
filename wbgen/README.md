# wbgen — генератор карточек Wildberries в минимализме

Инструмент собирает комплект карточек для WB из **конфига ниши + данных товара**:
8 слайдов воронки (обложка-хук → боль/решение → преимущества → материалы →
характеристики → сценарий → отзывы/сравнение → CTA) в двух пропорциях —
**1080×1080** и **900×1200** (основной формат WB) — плюс контактный лист,
HTML-превью и авто-QA.

Контент и стиль ниши живут только в JSON-конфигах: **новая ниша добавляется одним
файлом без правок кода**, новый товар — одним файлом с данными и фото.

## Структура

```
wbgen/
  content/
    niches/<ниша>.json           # палитра, гарнитуры, тон голоса, лейблы, требования
    products/<ниша>/<товар>.json # контент воронки + фото
  assets/fonts/                  # Inter (OFL) и Prata (OFL), с кириллицей
  src/                           # движок: дизайн-система, шаблоны, рендер, QA
  output/<ниша>/<товар>/         # результат рендера (коммитится для просмотра)
    square/01-cover.png … 08-cta.png
    vertical/01-cover.png … 08-cta.png
    contact-sheet.png            # сетка всех слайдов для быстрого просмотра
    preview.html                 # самодостаточное превью с заметками и итогом QA
    qa-report.json               # протокол авто-QA
```

## Запуск

```bash
npm run wbgen -- list                              # ниши и товары
npm run wbgen -- render --product jewelry/ring-emerald  # один комплект
npm run wbgen -- render --all                      # все комплекты
npm run wbgen:typecheck                            # типы движка
```

Рендер детерминирован: шрифты берутся только из `wbgen/assets/fonts`,
системные не подключаются. Зависимости рендера: `@resvg/resvg-js` (SVG→PNG),
`opentype.js` (метрики текста для вёрстки и QA).

## Как добавить нишу (один конфиг)

Создайте `wbgen/content/niches/<id>.json` по образцу существующих:

```jsonc
{
  "id": "gifts",                    // латиницей, используется в путях
  "title": "Подарки и свечи",
  "description": "Короткое описание стиля ниши",
  "palette": {
    "background": "#F6F1EA",        // фон слайдов
    "ink": "#2E2A26",               // чернильный текст (контраст ≥ 4.5:1 проверит QA)
    "muted": "#6E675C",             // вторичный текст, капитель-лейблы
    "accent": "#B4543A",            // ровно один акцент
    "photoBg": "#EAE2D3"            // фон фото-зоны / плейсхолдера
  },
  "typography": {
    "primary": "Inter",             // основной гротеск (Inter или Prata из ассетов)
    "accent": null,                 // опциональный сериф для премиум-ниш
    "headlineFont": "primary",      // чем набирать заголовки
    "quoteFont": "primary",
    "capsTrackingEm": 0.18          // трекинг капители
  },
  "photo": { "style": "warm-macro", "note": "подсказка по съёмке" },
  "voice": {
    "tone": "описание тона",
    "hookMax": 45, "subMax": 90, "bulletMax": 40, "badgeMax": 12,
    "rowValueMax": 30, "quoteMax": 160,
    "noExclaims": true,             // запрет «!»
    "bannedWords": ["уникальный", "высокое качество", "лучший"]
  },
  "labels": {
    // шапки слайдов (ключи label*) + предметные лейблы ниши
    "labelPain": "Задача", "labelBenefits": "Преимущества",
    "labelQuality": "Материалы", "labelSpecs": "Характеристики",
    "labelScenario": "В жизни", "labelProof": "Сравнение", "labelCta": "Заказ",
    "scent": "Аромат", "burnTime": "Время горения"
  },
  "requirements": [                 // обязательные элементы ниши (проверяет QA)
    { "slide": "specs", "specRowKeys": ["scent", "burnTime"] }
  ]
}
```

## Как добавить товар

`wbgen/content/products/<ниша>/<id>.json` — ровно 8 слайдов в порядке воронки
(порядок типов проверяется загрузчиком):

```jsonc
{
  "id": "candle-amber",
  "niche": "gifts",
  "title": "Свеча «Амбер»",
  "placeholder": "candle",                 // вид демо-силуэта
  "photos": {                              // реальные фото, пути от корня репо
    "hero": "wbgen/assets/products/candle-amber/hero.png",
    "macro": "…",
    "scenario": "…"                        // любой слот можно опустить
  },
  "slides": [
    { "type": "cover", "hook": "…", "badges": ["…"], "note": "хинт для LLM" },
    { "type": "pain", "hook": "…", "sub": "…" },
    { "type": "benefits", "bullets": ["…", "…", "…"] },
    { "type": "quality", "rows": [["Материалы", "…"], ["…", "…"]] },
    { "type": "specs", "rows": [["Аромат", "…"], ["Время горения", "…"]] },
    { "type": "scenario", "sub": "…" },
    { "type": "proof", "compare": { "title": "…", "columns": ["…", "…"], "rows": [["…", "…", "…"]] } },
    { "type": "cta", "cta": "…", "sub": "…" }
  ]
}
```

Поля совместимы с воронкой студии (hook/подзаголовок/буллеты/бейджи/заметки),
поэтому тексты позже можно генерировать внешней LLM: заметка `note` — готовый
хинт для промпта, лимиты длин и слова-воды уже описаны в `voice` ниши.

### Фото

- Фото подставляется **только через конфиг** товара (`photos.hero/macro/scenario`),
  PNG/JPEG, путь от корня репозитория; вписывается в зону cover-кропом.
- Если файла нет — используется явно помеченный демо-плейсхолдер (силуэт в
  стиле ниши с капителью DEMO). Верстка от плейсхолдера не зависит.
- Текст на фото не размещается — подписи живут на фоне слайда (QA следит).

## Авто-QA

После рендера каждого слайда проверяется:

| проверка | что ловит |
|---|---|
| `contrast` | контраст текста к подложке ≥ 4.5:1 (WCAG) |
| `overflow` | выход текста за край, обрезку по лимиту строк |
| `preview300` | читаемость заголовка (≥15px) и чипа (≥8px) в превью 300px |
| `safe-zone` | поля сетки и угловые сервисные зоны маркетплейса |
| `photo-overlap` | текст поверх реального фото |
| `meanings`, `text-overlap` | ≤3 смыслов на слайд, наложения текстов |
| `voice-limit`, `banned-word` | лимиты длин ниши, слова-воды, «!» |
| `niche-requirement` | обязательные строки/бейджи ниши |

Провал любой проверки → причина в консоли и `qa-report.json`, комплект
**останавливается** (без контактного листа и превью), команда возвращает код 1.
Тихих прогонов нет.

## Где смотреть результат

1. `wbgen/output/<ниша>/<товар>/contact-sheet.png` — обе пропорции одним листом.
2. `preview.html` — открыть в браузере: слайды, заметки, палитра, итог QA.
3. `qa-report.json` — протокол проверок.

## Дизайн-система (кратко)

- Воздух 60–70%, один фокальный объект, без градиентов/объёмных теней/блобов.
- Цвета: фон ниши + чернильный текст + один акцент; чипы — outline,
  лейблы — капитель с трекингом.
- Максимум две гарнитуры; hairline-разделители; поля сетки и угловые зоны
  маркетплейса проверяются автоматически.
- Токены заданы на сетке 1080 и масштабируются на 900×1200
  (`s = min(W,H)/1080`), поэтому оба формата строятся из одних данных.
